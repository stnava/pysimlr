1. Authoritative Rationale: SiMLR vs. Flow-SiMR

Mathematical & Architectural Correction

User Directive: "seems like it should be Flow-SiMR and Flow-SIMR-V instead of Flow-SiMLR and Flow-SiMLR-V"

Theoretical Rationale: In classical multi-modal literature, SiMLR designates Similarity-driven Multimodal Linear Representation (or Reconstruction). The letter "L" explicitly signifies linearity. Because Normalizing Flows are bijective, non-linear diffeomorphic coordinate transformations composed of stacked affine coupling layers, the resulting architecture is fundamentally non-linear. Retaining "L" is an architectural misnomer.

Codebase Synchronization: This correction establishes 1:1 parity with the underlying Python implementations in src/pysimlr/flows.py:

  • class FlowSiMRModel(nn.Module) → Flow-SiMR (Ours)
  • class FlowSiMRVModel(nn.Module) → Flow-SiMR-V (Ours)
  • def flow_simr(...) → Training functional for Flow-SiMR
  • def flow_simr_v(...) → Training functional with OLEE linear encoder bottleneck
